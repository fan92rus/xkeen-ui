AWG — мультисервер (макет UI)

Концепт добавления второго/третьего AWG-сервера с разными обфускациями. Стиль согласован с существующим AwgTab.vue.
ℹ Оба сервера поднимаются независимо. Каждый имеет свой порт, подсеть и профиль обфускации. Правила файрвола и восстановление после сноса NDMS работают для всех активных серверов автоматически.

⚠ Порт должен отличаться от уже используемых (сейчас: 443). Подсеть не должна пересекаться с существующими (10.8.0.0/24). NDMS-интерфейс OpkgTun1 должен быть создан в системном конфиге Keenetic — см. шаг 4.
📋Что сделает мастер
  1. Сгенерирует /opt/etc/awg/opkgtun1.conf (новый PrivateKey, ListenPort, обфускация, Address 10.8.1.1/24)
  2. Покажет команды для NDMS (создание OpkgTun1) — или выполнит их сам, если xkeen-ui на роутере
  3. После создания netdev: Up → attach amneziawg-go → Apply firewall (port 4443, subnet 10.8.1.0/24, WAN/LAN)
  4. Сервер появится в списке, NDM-хук будет его ресторить при каждом сносе файрвола

⚙️Создание OpkgTunN в NDMS (шаг перед «Добавить сервер»)

xkeen-ui не создаёт NDMS-интерфейсы сам (это прерогатива прошивки). Ниже — команды, которые нужно выполнить один раз через SSH/CLI Keenetic. После этого netdev появится и attach-режим заработает.

interface OpkgTun1 description AWG-Server-2 security-level private ip address 10.8.1.1 255.255.255.0 mtu 1420 adjust-mss pmtu up exit system configuration save
  • ✓ OpkgTun0 уже создан (существующий сервер)
  • ○ OpkgTun1 — нужно создать (команды выше)
  • ○ Файрвол/маршрут NDMS добавит сам при up интерфейса
ℹ Альтернатива: xkeen-ui может выполнить эти команды сам, если запущен на роутере (через ndmc). В макете — ручной вариант для прозрачности и безопасности.
🛡️Что меняется в коде (backend)
  • Новый эндпоинт POST /api/awg/server/create — принимает name, subnet, port, obfuscation preset; валидирует уникальность имени/порта/подсети; генерирует PrivateKey (awg genkey); пишет .conf
  • Валидация конфликтов: порт уже занят → 409; подсеть пересекается с существующей → 409; имя не opkgtunN → 400
  • Attach-режим уже работает per-netdev (isOpkgTunAttachMode) — второй сервер поднимется через тот же путь
  • Firewall restore уже итерирует все активные серверы (RestoreAWGServerFirewalls) — второй сервер автоматически получит правила
  • NDM-хук уже делает POST restore-firewall на каждый rebuild — покрывает все серверы
  • Удаление: teardown + glob-cleanup runtime .set + сообщение «NDMS-интерфейс останется — удалите вручную»
  • Миграция S91: хардкод opkgtun0 убрать — attach-режим + хук покрывают всё
